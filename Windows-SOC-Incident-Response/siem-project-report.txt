SIEM INVESTIGATION REPORT
Project: End-to-End Windows SOC Detection & Incident Response Lab
SIEM: Wazuh
Endpoint: Windows 10 (WINDOWS10-SOC)
Wazuh Agent: 4.14.8
Wazuh Server: Ubuntu 24.04.5 LTS
Environment: Isolated VirtualBox lab

1. OBJECTIVE
This lab demonstrates a basic SOC monitoring and incident-investigation workflow using Windows Event Logs, Sysmon, a Wazuh agent, and the Wazuh SIEM platform. Security activity was intentionally generated in an isolated lab and investigated through collected telemetry and alerts.

2. SIEM ARCHITECTURE
Windows 10 endpoint
    -> Wazuh Agent
    -> Wazuh Manager / Indexer
    -> Wazuh Dashboard
    -> Search, alert triage, investigation, evidence collection

The Windows endpoint was registered as WINDOWS10-SOC and reached Active status.

3. INCIDENT 001 - FAILED LOGON
Detection: Windows Security Event ID 4625
Wazuh Rule ID: 60122
Rule Description: Logon Failure - Unknown user or bad password
Rule Level: 5

Key findings:
- Agent: WINDOWS10-SOC
- Target account: SOCtest
- Logon Type: 2
- Failure reason: Unknown user name or bad password
- Source IP: 127.0.0.1
- Workstation: WINDOWS10
- Process: C:\Windows\System32\svchost.exe
- Authentication package: Negotiate
- Event channel: Security

Analysis:
The failed-logon activity was intentionally generated by entering an incorrect password for the SOCtest account in the isolated lab. Wazuh successfully received the Windows Security event and generated a rule-based alert.

Assessment: Benign / Expected Lab Activity.

SOC relevance:
Repeated failed logons can indicate password guessing or brute-force activity. An analyst should review the account, source address, timing, logon type, and surrounding events before determining severity.

4. INCIDENT 002 - POWERSHELL PROCESS INVESTIGATION
Detection source: Sysmon Event ID 1 - Process Create

Key findings:
- Process: C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe
- Command line: "C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe" -NoProfile -Command Get-Date
- User: WINDOWS10\vboxuser
- Process ID: 2052
- Integrity Level: Medium
- Parent image: C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe
- Current directory: C:\Users\vboxuser\

Analysis:
Sysmon recorded PowerShell process creation on the Windows endpoint. The command used in the lab was a harmless Get-Date command. The process, command line, user, parent process, and integrity level were reviewed to understand the execution context.

Assessment: Benign / Expected Lab Activity.

SOC relevance:
PowerShell is a legitimate administration tool but can also be abused by attackers. Analysts should investigate command line, parent process, user, integrity level, scripts, and related network activity when execution is unexpected.

MITRE ATT&CK: T1059.001 - PowerShell.

Note:
The event was treated as Sysmon telemetry/investigation evidence rather than claimed as a successful Wazuh alert.

5. INCIDENT 003 - SCHEDULED TASK REGISTRATION
Detection source: Windows Task Scheduler Operational log
Event ID 106 - Task Registered

Key findings:
- Task name: \SOC-Lab-Test
- User context: WINDOWS10\vboxuser
- Host: windows10
- Action: cmd.exe /c echo SOC Lab Test
- Schedule: One Time Only
- Event channel: Microsoft-Windows-TaskScheduler/Operational

Analysis:
A harmless scheduled task was intentionally created to demonstrate persistence-related monitoring. Event ID 106 showed the task name, user context, command, schedule, and host.

Assessment: Benign / Expected Lab Activity.

SOC relevance:
Scheduled tasks are legitimate Windows functionality but can also be abused for persistence. Analysts should investigate unexpected task creation, including the creator, command, schedule, and surrounding process activity.

MITRE ATT&CK: T1053.005 - Scheduled Task/Job: Scheduled Task.

Note:
The scheduled-task investigation used the Windows Task Scheduler evidence already collected in the lab. It was not claimed as a successful Wazuh alert when no corresponding alert was returned in wazuh-alerts-*.

6. SIEM OPERATIONS PERFORMED
- Installed Wazuh all-in-one on Ubuntu.
- Connected the Windows 10 endpoint with the Wazuh Agent.
- Verified the endpoint reached Active status.
- Configured Windows Security and Sysmon event-channel collection.
- Investigated Wazuh alert data in Discover.
- Filtered events by agent name and event identifiers.
- Investigated a real Wazuh alert for Windows Event ID 4625.
- Reviewed Sysmon process-creation telemetry for PowerShell.
- Reviewed scheduled-task registration telemetry.
- Collected screenshots as technical evidence.
- Classified each lab incident as benign based on the known test context.

7. SOC INCIDENT RESPONSE WORKFLOW
Generate controlled activity
    -> Detect / collect telemetry
    -> Filter and investigate
    -> Review user, process, time, source and command details
    -> Determine benign or suspicious
    -> Map relevant behavior to MITRE ATT&CK
    -> Preserve evidence
    -> Document findings and response

8. KEY LESSONS LEARNED
- Event ID 4625 is useful for monitoring failed authentication.
- Sysmon Event ID 1 provides detailed process-creation telemetry.
- PowerShell requires contextual analysis because it can be both legitimate and abused.
- Scheduled tasks should be reviewed when their creation is unexpected because they can support persistence.
- A SIEM centralizes endpoint telemetry and makes investigation easier than checking isolated logs manually.
- Not every collected event necessarily becomes a SIEM alert.
- Evidence should contain the event details supporting the investigation and final assessment.

9. FINAL ASSESSMENT
This project demonstrates an entry-level SOC workflow using a Windows endpoint, Sysmon, Wazuh, event investigation, alert triage, evidence collection, and MITRE ATT&CK concepts.

The lab is intentionally isolated and uses benign test activity. It should be presented as a student cybersecurity/SOC lab project, not as enterprise SOC employment experience.
